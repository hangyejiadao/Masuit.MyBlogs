# 博客打赏：支付宝当面付（扫码支付）接入说明

> 适用版本：本分支 `feature/alipay-face-to-face`。打赏功能位于文章详情页底部（版权声明下方、评论区上方），访客点击「☕ 打赏作者」即可扫码支付。

## 一、为什么用当面付，不用电脑网站支付

| 支付产品 | 适用场景 | 是否需要域名 ICP 备案 |
|---|---|---|
| 电脑网站支付（`alipay.trade.page.pay`） | 用户在浏览器里跳转支付宝收银台付款 | **需要**：支付页面挂在自有域名上，支付宝要求域名完成 ICP 备案 |
| **当面付（`alipay.trade.precreate`，本次打赏用的）** | 生成支付二维码，用户用支付宝 App 扫码付款 | **不需要**：付款全程在支付宝 App 内完成，自有域名上不挂支付页面，只需一个公网可达的异步通知地址 |

本站商店（软件购买）沿用电脑网站支付（见《软件购买与支付宝支付说明.md》）；打赏改用当面付，**不需要给域名做 ICP 备案**，个人开发者也能开通。

## 二、在支付宝开放平台申请当面付

1. 登录 [支付宝开放平台](https://open.alipay.com)，用支付宝账号创建应用（类型选「网页/移动应用」均可，名称如「Masuit 博客」）。
2. 在应用详情页「产品绑定」中签约 **当面付**：
   - 个人账号可直接签约（当面付支持个人商户），按提示提交营业执照/身份证信息并完成审核；
   - 签约时不需要填写网站域名和 ICP 备案号（当面付不校验域名备案）。
3. 在「开发设置」里配置密钥（二选一，推荐第一种）：
   - **推荐：证书模式**——下载开放平台密钥工具，生成 RSA2 密钥对，把应用公钥上传到平台；
   - 或「公钥模式」——同样生成 RSA2 密钥对，把应用公钥填到平台。
   - 生成后平台会给出一个 **支付宝公钥**（注意：支付宝公钥 ≠ 你上传的应用公钥，配置时不要填错）。
4. 记下应用的 **AppId**（如 `2024xxxxxxxxxxxx`）。
5. 在应用详情页「功能列表」确认当面付已是「已生效」状态。

> 沙箱联调：开放平台提供沙箱应用（AppId 以 `20210001` 开头），沙箱买家账号在沙箱控制台领取；沙箱网关地址见下方配置说明。

## 三、配置（appsettings.json）

在服务器上的 `src/Masuit.MyBlogs.Core/appsettings.json` 里填写 `Alipay` 一节（仓库里的文件只留空占位值，**真实密钥绝不能提交到代码仓库**）：

```json
"Alipay": {
    "Enabled": true,
    "AppId": "2024xxxxxxxxxxxx",
    "PrivateKey": "MIIEvQIBADANBgkqhkiG9w0BAQEFAASC...（应用私钥，PKCS8 格式，单行）",
    "AlipayPublicKey": "MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCg...（支付宝公钥）",
    "Gateway": "https://openapi.alipay.com/gateway.do",
    "NotifyUrl": "",
    "ReturnUrl": "",
    "DonateNotifyUrl": "https://你的域名/DonatePay/AlipayNotify"
}
```

| 配置项 | 说明 |
|---|---|
| `Enabled` | 总开关。`false` 时打赏和商店支付都不可用，前端点击生成二维码会提示「支付宝支付未启用」 |
| `AppId` | 开放平台应用的 AppId |
| `PrivateKey` | 应用私钥（商户私钥，PKCS8 格式）。用开放平台密钥工具生成，与上传到平台的应用公钥配对；**只能填在服务器的配置文件里**，不要写进代码、不要提交到 Git |
| `AlipayPublicKey` | 平台生成的支付宝公钥，用于校验支付宝异步通知的签名 |
| `Gateway` | 正式环境 `https://openapi.alipay.com/gateway.do`；沙箱联调改成 `https://openapi-sandbox.dl.alipaydev.com/gateway.do` |
| `NotifyUrl` / `ReturnUrl` | 商店支付用，留空自动用当前站点域名拼接（见商店支付文档） |
| `DonateNotifyUrl` | **打赏专用**异步通知地址。留空自动用 `https://当前站点域名/DonatePay/AlipayNotify`；建议显式填写 |

配置与商店支付共用同一套应用凭据（AppId/私钥/支付宝公钥），但当面付和电脑网站支付需要在开放平台分别签约对应产品。

## 四、回调地址怎么配

支付宝付款成功后，会向 `DonateNotifyUrl` 发送 **POST 异步通知**（服务器对服务器），博客收到后验签并把订单置为已支付、写入打赏记录。

- **地址要求**：必须是公网可达的 `https` 地址（支付宝不接受 `http`，也不接受内网地址）。路径固定为 `/DonatePay/AlipayNotify`，不需要在开放平台逐个登记——通知地址由创建订单时传给支付宝（`notify_url` 参数），以这里配置的值为准。
- **本地联调**：本地开发机没有公网地址时，用内网穿透（如 ngrok / frp）把本地端口映射到公网域名，再把 `DonateNotifyUrl` 填成穿透地址；或者先不配回调，只用前端轮询查单（见下）。
- **即使回调收不到，钱也不会丢**：前端每 3 秒轮询一次 `GET /DonatePay/QueryStatus?orderNo=...`，直接向支付宝查单（`alipay.trade.query`），支付成功后同样会把订单置为已支付。回调是「实时到账提醒」，轮询是「兜底」，两者都走同一套幂等标记逻辑（Redis 分布式锁 + 订单状态重查），重复通知不会重复记账。

## 五、打赏流程（技术实现）

```
访客选金额/填昵称/留言
  → POST /DonatePay/Create（匿名接口，不登录也能打赏）
      → 建 DonateOrder（订单号 DONATE + 时间戳 + 4 位随机数，状态：待支付）
      → alipay.trade.precreate 生成支付二维码（有效期 2 小时，超时自动关闭）
  → 前端展示二维码，访客用支付宝 App 扫码付款
  → 支付宝回调 POST /DonatePay/AlipayNotify（RSA2 验签 → 校验 AppId/订单号/金额 → 幂等标记已支付 → 写 Donate 记录，Via=支付宝当面付）
  → 前端轮询 GET /DonatePay/QueryStatus 发现已支付 → 显示「支付成功，感谢打赏！」
```

关键文件：

| 文件 | 作用 |
|---|---|
| `src/Masuit.MyBlogs.Core/Models/Entity/DonateOrder.cs` | 打赏订单实体（订单号、昵称、留言、金额、状态、创建时间、支付时间、支付宝交易号、二维码内容） |
| `src/Masuit.MyBlogs.Core/Infrastructure/Migrations/20261111154943_AddDonateOrder.cs` | EF Core 迁移：新建 `DonateOrder` 表（订单号唯一索引、创建时间倒序索引）；应用启动时自动迁移 |
| `src/Masuit.MyBlogs.Core/Controllers/DonatePayController.cs` | 公开接口：`POST /DonatePay/Create`（创建订单+二维码）、`GET /DonatePay/QueryStatus`（查单）、`POST /DonatePay/AlipayNotify`（异步通知） |
| `src/Masuit.MyBlogs.Core/Infrastructure/Services/AlipayPayService.cs` | 当面付调用：`CreatePrecreateQrAsync`（预下单）、`QueryTradeAsync`（查单），RSA2 签名与支付宝响应验签 |
| `src/Masuit.MyBlogs.Core/Infrastructure/Services/Interface/IAlipayPayService.cs` | 上述两个方法的接口定义 |
| `src/Masuit.MyBlogs.Core/Configs/AlipayConfig.cs` | 配置模型，新增 `DonateNotifyUrl` |
| `src/Masuit.MyBlogs.Core/Views/Post/Details.cshtml` | 文章页打赏弹窗：选金额（1/5/10/20/50/100 或自定义 0.01–10000 元）、二维码展示（qrcodejs CDN 渲染）、3 秒轮询、2 小时倒计时 |
| `src/Masuit.MyBlogs.Core/Models/Entity/Donate.cs`（已存在，未改） | 支付成功后自动写一条 `Donate` 记录（Via=支付宝当面付），后台「打赏管理」里可见 |

## 六、金额与订单规则

- 金额范围 **0.01–10000 元**，最多 2 位小数；超出范围创建订单时直接拒绝。
- 二维码有效期 **2 小时**（`timeout_express=2h`），过期后支付宝自动关闭订单，前端倒计时到 0 会提示重新下单。
- 订单号格式：`DONATE` + `yyyyMMddHHmmss` + 4 位随机数（如 `DONATE202611111549430123`），全局唯一。
- 订单状态：`待支付`（Pending）→ `已支付`（Paid）或 `已关闭`（Closed，超时/支付宝关单时）。已支付的订单不可重复标记，重复回调直接返回 `success`。

## 七、后台管理

- 支付成功后自动写 `Donate` 记录，可在后台「打赏管理」（`DonateController`）查看、筛选和导出；`DonateOrder` 表保留完整订单与支付宝交易号（`AlipayTradeNo`），用于对账。
- 对账：拿 `DonateOrder.AlipayTradeNo` 到支付宝商家后台「交易管理」核对即可。

## 八、常见问题

- **点击生成二维码提示「支付宝支付未启用」**：检查 `Enabled` 是否为 `true`，以及 `AppId`/`PrivateKey`/`AlipayPublicKey` 是否都已填写。
- **生成二维码失败，日志报签名错误**：私钥格式不对。私钥必须是 PKCS8 格式（以 `MIIE...` 开头的一行字符串，不要带 `-----BEGIN PRIVATE KEY-----` 头尾，程序会自动兼容带头尾的格式）；确认上传到开放平台的应用公钥与这份私钥是同一对。
- **扫码支付后页面一直显示「等待支付」**：先看回调地址是否公网可达（支付宝回调失败会在商家后台看到通知记录）；即使回调失败，前端轮询也会在 3 秒内发现已支付并自动跳转成功页。
- **沙箱测试**：把 `Gateway` 换成沙箱地址、`AppId`/`PrivateKey`/`AlipayPublicKey` 换成沙箱应用的，用沙箱买家账号扫码付款；正式上线前记得换回正式网关和正式应用凭据。
- **密钥泄露了怎么办**：立即在开放平台重新生成密钥对，更新服务器配置并重启应用；旧密钥作废后，泄露的私钥即失效。
