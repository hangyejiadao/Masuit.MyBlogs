# 端口转发说明

后台功能，仅管理员登录后可访问。入口在新版后台（Vue）左侧菜单「端口转发」。

功能：维护转发规则，把流量转发到指定的目标主机端口，有两种相互独立、可同时启用的方式：

- **TCP 端口转发**：在博客所在机器的某个监听端口收连接，双向转发到目标。典型用途是把内网服务（数据库、内部站点、其他机器的服务）通过博客服务器的公网端口段暴露出来。
- **路径转发（HTTP 代理）**：规则可选填一个路径前缀，博客收到该路径的 HTTP 请求就代理转发到目标（见下文专节）。典型用途是把只能走 HTTP 的服务（如 MCP）挂到博客域名下，不占用额外端口。

规则的新增、修改、删除、启停都会即时同步到转发引擎，不需要重启应用。

## 端口段限制（重要）

- **监听端口只能填 10000-10100**。博客运行在 Docker 容器中，部署时只有 10000-10100 这个端口段会发布（映射）到宿主机；监听端口填区间外的值，即使在容器内监听成功，外部流量也进不来，所以保存时直接拦截并给出提示。
- 监听端口全局唯一（数据库唯一索引兜底），不能与博客自身端口 5000（HTTP）和 465（邮件）相同——这两个端口本身也已在发布段之外，会先被端口段规则拦下，双重保险。
- 目标地址是从**博客容器视角**可达的地址：可以填容器内的服务名、宿主机内网 IP、局域网其他机器 IP 或公网地址；填 `127.0.0.1` 指的是容器自身，不是宿主机。

## 运行时行为

- 转发引擎（`PortForwardRuntime`，单例宿主服务）随应用启动加载全部启用规则逐一监听；单条规则监听失败（端口被占用等）只把该规则标为失败并记录日志，不影响应用启动和其他规则。
- 列表页展示每条规则的实时状态：监听中 / 已停用 / 失败原因，以及当前活跃连接数、累计连接数与累计转发字节数（双向合计）。状态为进程内实时数据，应用重启后计数清零，属正常现象。
- 目标连接超时为 15 秒；连接目标失败时只断开该连接并记录日志，不影响监听本身。
- 页面提供手动刷新查看最新状态，不做自动轮询。

## 路径转发（HTTP 代理）

规则上的「路径」字段可空：**留空 = 不启用路径转发**（行为与纯 TCP 规则完全一致）；填了（如 `/mcp`）则启用：

- **匹配**：博客收到 HTTP 请求时，请求路径等于某启用规则的路径、或以「路径 + /」开头（段边界，不会把 `/mcpfoo` 误匹配到 `/mcp`）即命中；多条规则路径重叠时**最长前缀优先**。匹配不区分大小写。未命中任何规则的请求按博客原有逻辑处理，几乎零开销。
- **剥前缀转发**：规则路径只是博客侧的挂载前缀，只负责匹配和路由，转发时**剥掉**。目标 URL = `http://{目标地址}:{目标端口}{剩余路径}{查询串}`，剩余路径是请求路径去掉规则前缀的部分；请求恰好等于前缀时，剩余为空，转到目标根路径 `/`。例：规则路径 `/mcp`、目标 `47.93.34.219:88`，请求 `https://hangyejiadao.vip/mcp/mcp/foo/bar?x=1` → 实际请求 `http://47.93.34.219:88/mcp/foo/bar?x=1`（第一个 `/mcp` 被剥掉，第二个 `/mcp` 起是子路径，原样保留）。
- **透明代理**：请求方法、请求头（Authorization、Content-Type、Mcp-Session-Id 等自定义头都透传；逐跳头如 Connection、Host 跳过，Host 改为目标的）、请求体原样转发；响应状态码、响应头、响应体原样回传。响应**逐块流式回传并立即冲刷、不做缓冲**，支持 SSE 长连接（为 MCP 的 Streamable HTTP 而设计）。
- **失败处理**：目标连不上等代理失败返回 **502** 并记录日志，不影响博客其他请求；客户端主动断开则直接收尾。
- **与 TCP 监听的关系**：相互独立、同一条规则可同时启用。路径转发走的是博客自身的 HTTP(S) 入口（域名 + 443），**不受 10000-10100 端口段与宿主机端口发布、安全组放行的限制**；TCP 监听则仍受端口段约束。代理流量计入该规则的同一套运行时统计（活跃连接、累计连接、累计字节：请求体 + 响应体都算）。
- **保留前缀**：路径不得与博客自身路由冲突，以下前缀（等于或落在其下）禁止使用，保存时直接拦截：`/dashboard`、`/passport`、`/home`、`/api`、`/account`、`/static`、`/wwwroot`、`/post`、`/comment`、`/search`、`/category`、`/tag`、`/author`、`/login`、`/register`、`/short`、`/signin-github`、`/signin-google`、`/_blazor`、`/health`、`/taskcenter`、`/portforward`、`/upload`、`/file`、`/share`、`/subscribe`、`/vedio`、`/serviceunavailable`。
- **格式要求**：必须以 `/` 开头、长度 2-128、不能以 `/` 结尾、不能包含空格或 `..`；多条规则之间路径不得相同（不区分大小写）。

## 接口清单

全部接口需管理员登录（`[MyAuthorize]`），返回统一信封 `{ Success, Message, Data }`：

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/PortForward/PortForwardPage` | GET | 规则分页查询，参数 `page`、`size`、`keyword`（按名称/目标/备注筛选）；返回规则字段（含 `Path`）合并运行时状态：`IsListening`、`StatusMessage`、`ActiveConnections`、`TotalConnections`、`TotalBytes` |
| `/PortForward/SavePortForward` | POST | 新建或修改规则（`Id=0` 为新建），含全部校验（含路径格式、保留前缀、路径不重复）；保存成功后同步转发引擎立即生效 |
| `/PortForward/DeletePortForward` | POST | 删除规则（参数 `{ Id }`），删除后立即卸载对应监听，无引用限制 |

## 数据表

- `PortForwardRule`（规则：名称、监听端口、目标地址、目标端口、路径、是否启用、备注），随 EF 迁移 `AddPortForwardRules` 创建；`ListenPort` 建有唯一索引。路径字段 `Path`（可空，≤128）由后续迁移 `AddPortForwardPath` 追加。
