# 端口转发说明

后台功能，仅管理员登录后可访问。入口在新版后台（Vue）左侧菜单「端口转发」。

功能：维护 TCP 端口转发规则，把博客所在机器的某个监听端口收到的连接，双向转发到指定的目标主机端口。典型用途是把内网服务（数据库、内部站点、其他机器的服务）通过博客服务器的公网端口段暴露出来。规则的新增、修改、删除、启停都会即时同步到转发引擎，不需要重启应用。

## 端口段限制（重要）

- **监听端口只能填 10000-10100**。博客运行在 Docker 容器中，部署时只有 10000-10100 这个端口段会发布（映射）到宿主机；监听端口填区间外的值，即使在容器内监听成功，外部流量也进不来，所以保存时直接拦截并给出提示。
- 监听端口全局唯一（数据库唯一索引兜底），不能与博客自身端口 5000（HTTP）和 465（邮件）相同——这两个端口本身也已在发布段之外，会先被端口段规则拦下，双重保险。
- 目标地址是从**博客容器视角**可达的地址：可以填容器内的服务名、宿主机内网 IP、局域网其他机器 IP 或公网地址；填 `127.0.0.1` 指的是容器自身，不是宿主机。

## 运行时行为

- 转发引擎（`PortForwardRuntime`，单例宿主服务）随应用启动加载全部启用规则逐一监听；单条规则监听失败（端口被占用等）只把该规则标为失败并记录日志，不影响应用启动和其他规则。
- 列表页展示每条规则的实时状态：监听中 / 已停用 / 失败原因，以及当前活跃连接数、累计连接数与累计转发字节数（双向合计）。状态为进程内实时数据，应用重启后计数清零，属正常现象。
- 目标连接超时为 15 秒；连接目标失败时只断开该连接并记录日志，不影响监听本身。
- 页面提供手动刷新查看最新状态，不做自动轮询。

## 接口清单

全部接口需管理员登录（`[MyAuthorize]`），返回统一信封 `{ Success, Message, Data }`：

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/PortForward/PortForwardPage` | GET | 规则分页查询，参数 `page`、`size`、`keyword`（按名称/目标/备注筛选）；返回规则字段合并运行时状态：`IsListening`、`StatusMessage`、`ActiveConnections`、`TotalConnections`、`TotalBytes` |
| `/PortForward/SavePortForward` | POST | 新建或修改规则（`Id=0` 为新建），含全部校验；保存成功后同步转发引擎立即生效 |
| `/PortForward/DeletePortForward` | POST | 删除规则（参数 `{ Id }`），删除后立即卸载对应监听，无引用限制 |

## 数据表

- `PortForwardRule`（规则：名称、监听端口、目标地址、目标端口、是否启用、备注），随 EF 迁移 `AddPortForwardRules` 创建；`ListenPort` 建有唯一索引。
